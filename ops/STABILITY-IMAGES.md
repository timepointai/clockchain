# One-image preparation

## Admitting a generated attachment

After visual review, `submit_image.py` creates a separate private media-writer
identity, signs the canonical manifest, and calls authenticated `POST /v1/images`.
The manifest binds an existing projected source body and a verified PNG object.
The node rejects missing/withdrawn source bodies, invalid signatures, wrong bytes,
and unsupported permission profiles. Base64 is transport encoding only; PNG files
are stored by digest on the app's dedicated persistent media volume.

`GET /v1/images?entity_id=…&as_of=…` lists attachments with current/stale binding
status. `GET /v1/images/{image_sha256}` serves the original PNG. Both require the
full or read credential. Narrow gallery/beta/telemetry credentials do not gain
access. Frozen nodes refuse submission. Existing historical events are unchanged.
Media manifests have independent signatures and are not covered by the historical
ledger anchors. Back up the media volume together with the attachment catalog.

The [media integrity assertion](../docs/IMAGE-INTEGRITY.md) runs through
`/health/deep` and `ops/validate.py`. A source body projected by no moment is a
failing check, including after withdrawal or correction; stale attachments are
retained for inspection.

For explicit deliberate absence and all four per-reading media states, see
[typed media absence](../docs/TYPED-MEDIA-ABSENCE.md). Existing v1 callers keep
their current coarse response contract.

## Local SDXL route

`sdxl_image.py` uses the official SDXL 1.0 checkpoint locally under CreativeML
Open RAIL++-M. It pins a model revision, captures weight and license hashes, and
binds its candidate to a captured live entity body_hash. This license permits
training derivatives subject to restrictions and required downstream notices;
it is not unrestricted. The hosted-API grant requirement below does not apply
to this local model-license route. Generation does not automatically submit.

```sh
python3 ops/sdxl_image.py --prompt-file /private/path/prompt.txt \
  --source-entity /private/path/source-entity.json \
  --cache /private/path/model-cache --output /private/path/new-sdxl-candidate
```

Reference: https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/blob/462165984030d82259a11f4367a4eed129e94a7b/LICENSE.md

## Hosted API route

For an explicitly requested display preview, `--preview-only` generates without
a training grant and permanently marks the result `training_admission=excluded`.
This mode does not approve corpus use. It never submits an image to the ledger.
Omit `--approval` in this mode. The default training-candidate path still requires
the reviewed grant described below.

As of 2026-09-08, generation for an unrestricted downstream-training dataset is
blocked on permission evidence. No image has been generated by this tool in
production. Stability's API output ownership provision is not unrestricted
training permission: section 3.b.2 of the July 31, 2025 terms restricts competing
model development. The announced September 30, 2026 version explicitly covers
training from outputs. Do not treat that future version as already effective.

- https://stability.ai/2025-terms-of-service
- https://stability.ai/terms-of-service
- https://platform.stability.ai/docs/api-reference

The proposed API is Stable Diffusion 3.5 Large, one 16:9 PNG, one attempt, no
automatic retries. Generation is off-ledger. This tool has no node credentials,
submission integration, publication step, or automatic training admission.

## Storage

Preserve original PNG bytes as `<sha256>.png` beside `manifest.json` in a private
staging directory outside git. Base64 increases size by roughly one-third and
would repeat the old graph's inline-image database bloat. For production, use
object storage with object key `clockchain/images/sha256/<sha256>.png`; keep only
the key, hash, MIME type, size and provenance reference in application metadata.
No bucket or production schema is provisioned by this one-image tool.

Keep embedded content credentials/watermarks. Derivative thumbnails get separate
hashes. Mark generated imagery as synthetic illustration, never historical proof.
Prompt/provenance metadata is excluded from training by default; prompt sources
need their own rights review. Human visual review and permission review precede
any image admission. A JSON boolean alone does not establish rights.

## Run after permission is established

Provide a locally retained Stability grant covering the selected hosted model,
downstream training including competing models, and dataset redistribution.
An authorized reviewer must assess its scope before supplying this manifest:

```json
{
  "status": "blocked",
  "provider": "stability.ai",
  "model": "sd3.5-large",
  "training_including_competing_models": false,
  "dataset_redistribution": false,
  "reviewer": "",
  "reviewed_at": "2026-09-08",
  "valid_through": "2026-09-08",
  "grant_reference": "",
  "grant_file": "provider-grant.txt",
  "grant_sha256": ""
}
```

Use a rights-cleared prompt file. Set `STABILITY_API_KEY` through a secret manager
or secure environment injection; never put the key in arguments or tracked files.

```sh
python3 ops/stability_image.py --approval /private/path/permission.json \
  --prompt-file /private/path/prompt.txt --output /private/path/new-image-candidate
```

The default blocked manifest exits 2 before reading a prompt, reading a key,
creating output, or contacting Stability. Network generation remains untested
until suitable permission is available. This is a CLI, not a deployed feature.
