# Owner-only publication gate

Complete this checklist privately before a candidate leaves its private attempt
for publication. Record the reviewer, date, exact candidate digest, brief digest
and evidence references. An unchecked item blocks handoff. This document is a
review template, not an approval or a replacement for publisher checks.

- [ ] **Purpose chosen.** Record one decision: prepare this candidate as a public
  seed; retain it as a canonical private publication rehearsal; retain it privately
  for stronger sources; or leave production empty while hardening reads. Only the
  first proceeds toward publication. A completed rehearsal does not authorize
  publication or make its fixture the first public corpus.
- [ ] **Source excerpts adequate.** Read the complete candidate against retained,
  hash-verified captures and literal passages. Assess support for each claim,
  date, classification and relation. Record source limitations, reuse conditions,
  independent corroboration and contrary evidence. Literal matching alone does
  not establish adequacy; repeated use of one source is not corroboration.
- [ ] **Relations no stronger than evidence.** Review direction, chronology,
  relation type and each stated mechanism. Preserve distinctions between
  influence, production and causation. Record unsupported alternatives as such;
  do not strengthen a relation because it makes a more compelling chain.
- [ ] **Media decision made for each exact reading.** Review the original image,
  entity/body binding, disclosure and unsupported visual detail. Choose accepted
  synthetic illustration, withholding with no media write, or an explicit signed
  deliberate non-illustration decision. Regeneration after visual review is
  another private attempt, not a public pending state.
  Retain rejected
  or withdrawn preparations privately. A missing image, failed read or failed
  generation never establishes a deliberate decision. Signed image attachment
  admission is separate from claim publication; a prepared image or publication
  receipt does not establish attachment admission. A deliberate absence likewise
  needs its own owner-operated signed record.
  Withholding an image privately is a review decision, not an admitted absence
  record. Do not label it `deliberately_unillustrated` in deployed reads until the
  corresponding signed decision has actually been admitted.
  Withholding closes the media choice when the brief permits no images; it does
  not require a signed absence. Claims-only publication has no media readings in
  the updated node API; it does not create an absence verdict.
- [ ] **Historical verification recorded honestly.** Record the actual review,
  evidence consulted, limitations and unresolved questions. Keep historical
  assessment separate from visual acceptance and structural/signature checks.
  `not_assessed` remains visible when no assessment occurred. An accepted
  illustration remains synthetic; display or admission does not make it
  documentary evidence. Never promote a status merely to pass a gate.
- [ ] **Scope exclusion stated.** The owner records one line completing
  “What this record is not: …” in the private review. This is a review boundary,
  not permission for an assistant to rewrite model-authored historical content.
- [ ] **Exact handoff checked.** Run candidate validation with the exact brief,
  retain results, and verify all required media and provenance. Recheck live
  state and publication posture before the owner operates the existing handoff.
  Changes to candidate bytes or brief requirements require renewed review and
  exact approvals; earlier approvals do not transfer automatically.

Run the checklist separately for every node, edge and image. Record pass, narrow,
withhold or reject, the reviewer and supporting references for each object;
leave provisional judgments explicitly pending. There is no bundle pass. Compare
the summary with the actual stored historical claim: an attribution in one field
does not qualify an unqualified assertion in another. Source-date precision and
the date of a retrospective assertion must remain distinct.

Freeze a private inventory of proposal, brief, receipts, source captures and media
hashes before the rehearsal, then recheck it afterward. Any change invalidates the
review of those exact bytes; retain the old attempt and review the replacement.
Do not edit manifests or historical prose merely to close checklist items.

The owner records the scope-exclusion sentence and reviews how it will be conveyed
with any future published notes, together with relation type, evidence class and
mechanism limitations. Assess the graph as if it were the entire public corpus.
Publication is eligible only after every required item is a written decision;
there is no automatic date or publication action when this checklist completes.

Before any owner write, verify that the deployed default window still represents
the actual empty state and that failed reads remain errors. After an authorized
owner publication, retain the ordered operation receipts, entity/body bindings,
edge identifiers, media or absence decisions, coordinate and operator. Verify the
chosen set through the read-only browser, keep local and deployed records distinct,
and preserve the bounded-window label. Do not add records to improve the page.

The current required-image gate requires visual acceptance as an illustration,
an exact entity/body binding, `synthetic: true` and
`historical_verification: not_assessed`. It does not perform historical
verification. Withdrawing images cannot satisfy an images-required brief: the
owner must explicitly revise that requirement and review the new candidate and
brief. Never silently substitute absence for required images or relabel an image
as documentary to satisfy the implementation.

Initialization, staging, approval recording, signing, publication and media
admission remain human-operated for owner-designated content. The browser has no
publish controls. Assistant activity is limited to software, read-only checks and
preparing review material; historical content remains app/model-authored.

If the node API lacks complete stored claim prose needed for review, stop that
review at the limitation or inspect the retained private candidate. Address
retrieval in the node/API before relying on a deployed review; never reconstruct
claim prose from titles, hashes, classifications or images in the browser.
